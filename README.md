# Альфа Хак 2026 — Backend

Backend MVP сервиса персонализированной новостной аналитики для бизнеса. Реализован по зоне ответственности Backend Developer из ТЗ: FastAPI, SQLite, загрузка CSV и RSS, персональная лента, интерфейсы интеграции AI, сохранение инсайтов, вопросы, трассировка и Docker Compose.

## Состав

- `backend/main.py` — HTTP API, CORS, единый безопасный обработчик внутренних ошибок, trace ID и Swagger.
- `backend/models.py`, `backend/database.py` — SQLite-хранилище компаний, новостей, оценок ленты, инсайтов и вопросов.
- `backend/services/company_data.py` — импорт CSV с сохранением неизвестных полей как `null`.
- `backend/services/news.py` — асинхронный RSS-парсер, нормализация текста/дат и исключение точных дубликатов.
- `backend/services/personalization.py` — прозрачный базовый рейтинг, причины и факторы для CEO/CFO.
- `backend/services/insights.py` — кэширование результата и точка подключения `ai.agent.generate_insight` / `ai.agent.answer_question`, если AI-команда добавит модуль.

ML/AI директории пока не предоставлены. Пока они отсутствуют, API честно возвращает базовую оценку и fallback-анализ с пустой позицией банка; результат помечается `validation_status: fallback`. Текст fallback не является банковской аналитикой или результатом LLM. Подключение командных модулей выполняется через указанные Python-функции без изменения HTTP-контракта.

## Запуск

Нужен Docker с Docker Compose.

```bash
docker compose up --build
```

API: <http://localhost:8000>; Swagger: <http://localhost:8000/docs>; OpenAPI: <http://localhost:8000/openapi.json>.

Для локального запуска без Docker:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

Остановка Docker-версии: `docker compose down`. Для удаления локальной БД удалите `data/alpha_hack.db`.

## Данные

По умолчанию сервер создаёт три синтетических профиля для демонстрации разных отраслей. Это не реальные компании и не данные организаторов. Чтобы использовать данные кейса, поместите CSV юридических лиц в `data/companies.csv` до первого запуска и задайте `COMPANIES_CSV_PATH`, если файл находится в другом месте. Поддерживаются разделители `,` и `;`, UTF-8 и UTF-8 BOM. Ожидаемые колонки включают `SYNTHETIC_U`, `MAINOKVED_CODE`, `MAINOKVED_NAME`, `REVENUE_COMPANY`, `REGION`, `CITY`, `GROUP_ID`, `CL_PRODUCT_LOA_MARK`, `CL_PRODUCT_LEA_MARK`, `CL_PRODUCT_GAR_MARK`, `FTS_FLAG`, `FTS_COUNTRY_NAME`. Неизвестные значения не домысливаются. CSV исключён из Git.

Профиль загружается при первом запуске пустой БД. Если позже добавить исходный CSV, сбросьте локальную БД и перезапустите приложение, либо выполните импорт в рабочем процессе команды. Платёжные/контрагентские файлы не включены, так как в репозитории отсутствуют сами файлы и их фактическая схема.

## API

Все ответы — JSON. Для трассировки запросов сервер принимает `X-Trace-Id` или генерирует его сам и возвращает в заголовке ответа.

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Проверка приложения и БД |
| `GET /api/companies?q=&limit=` | Список и поиск по синтетическому ID |
| `GET /api/companies/{company_id}?role=ceo\|cfo` | Профиль и полнота данных |
| `GET /api/feed?company_id=&role=ceo\|cfo&limit=` | Персонализированная лента, сортирует backend |
| `GET /api/news/{article_id}?company_id=&role=` | Материал и, опционально, его оценка |
| `POST /api/news/refresh` | Ручная загрузка настроенных RSS источников |
| `POST /api/insights` | Создание или получение сохранённого инсайта |
| `GET /api/insights/{insight_id}` | Сохранённый инсайт |
| `POST /api/insights/{insight_id}/questions` | Контекстный уточняющий вопрос |
| `GET /api/insights/{insight_id}/questions` | История вопросов |
| `GET /api/insights/{insight_id}/trace` | Источники, шаги и статус проверки |

Пример тела `POST /api/insights`:

```json
{"company_id":"SYNTHETIC_U_001","article_id":"<id из /api/feed>","user_role":"cfo"}
```

Пример тела вопроса:

```json
{"question":"Как изменение ставки может повлиять на наши кредиты?"}
```

Ошибки возвращаются в `detail` с машинным `code` и безопасным сообщением; внутренние исключения не показываются клиенту. Основные статусы: 400 — неверный запрос, 403 — неверный токен ручного обновления, 404 — сущность отсутствует, 422 — ошибка схемы, 500 — внутренняя ошибка, 503 — RSS источники недоступны. Ранее сохранённые новости остаются доступны при сбое RSS.

## Интеграция ML/AI

Ожидаемые точки интеграции соответствуют ТЗ: `build_company_profile(company_id, user_role)`, `process_news(article)`, `rank_news(company_profile, articles)`, `generate_insight(company_profile, article, user_question=None)`. В текущем MVP профиль и ранжирование имеют прозрачные backend fallback реализации. При появлении модулей `ml` и `ai` их нужно подключить к этим сервисным границам; API-ключи остаются только на сервере. Повторный `POST /api/insights` для той же компании, новости и роли использует сохранённый анализ, не создавая нового запроса модели.

## Настройка

Скопируйте `.env.example` в `.env`. Параметры: `DATABASE_URL`, `CORS_ORIGINS`, `RSS_FEEDS`, `REQUEST_TIMEOUT_SECONDS`, `MAX_FEED_ITEMS`, `NEWS_REFRESH_TOKEN`, `COMPANIES_CSV_PATH`. Если задан `NEWS_REFRESH_TOKEN`, ручной endpoint обновления требует заголовок `X-Refresh-Token`. Не коммитьте `.env` и ключи моделей.

RSS настроен на ленты Банка России. Сбор происходит вручную по `POST /api/news/refresh`, чтобы не создавать скрытых фоновых задач в демонстрационном MVP. Таймаут, ограничение количества записей, обработка ошибок источника и дедупликация настроены. Разрешённость и доступность внешних источников следует перепроверить перед публичным развёртыванием.

## Ограничения MVP

- CSV-связи физических лиц и платежей не подключены: исходных таблиц нет.
- Персональный скоринг — объяснимый baseline, не финальная ML-модель и не финансовая рекомендация.
- Нет банковских аналитических документов и AI-агента в исходном репозитории; backend не заявляет неподтверждённую позицию банка.
- Корпоративная аутентификация/разграничение доступа не входит в демонстрационную версию.
- Для production следует добавить миграции схемы, ограничение частоты обновлений, планировщик и полноценную авторизацию.
