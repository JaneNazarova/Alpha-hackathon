# Альфа Хак 2026 — персональная новостная аналитика для бизнеса

Демонстрационный сервис, который загружает новости из RSS, связывает их с профилем компании, строит объяснимую персональную ленту и формирует AI-инсайт с уточняющими вопросами. Проект включает веб-интерфейс, REST API, ML-обработку данных и AI-агента.

## Возможности

- Поиск и просмотр обезличенных компаний, платежных агрегатов и связей из CSV кейса.
- Профиль компании с указанием доступных и отсутствующих данных.
- Импорт и дедупликация новостей из RSS Банка России.
- Объяснимое ранжирование новостей для ролей CEO и CFO.
- AI-интерпретация новости для конкретного профиля, сохранение результата и trace.
- Уточняющие вопросы по сохранённому инсайту.
- Веб-интерфейс для выбора компании и роли, просмотра ленты и инсайтов.
- Автоматические проверки backend, ML и контрактов API.

| Каталог/файл | Назначение |
|---|---|
| `backend/main.py` | ASGI-точка входа для Uvicorn |

| `backend/schemas.py` | Pydantic-схемы запросов и ответов API |
| `backend/services/` | Импорт данных, ML-адаптер, RSS и создание инсайтов |
| `ml/` | Индексация CSV, профилирование компаний, обработка новостей и ранжирование |
| `ai/` | LLM-клиент, агент, проверка результата, RAG-поиск и ответы на вопросы |
| `frontend/` | Статический интерфейс на HTML, CSS и JavaScript; адаптивная вёрстка без отдельной сборки |

Backend подаёт frontend с `/`, а CSS и JavaScript — через `/static`. Для локальной разработки отдельный frontend-сервер не требуется.

## Архитектура данных

На старте backend создаёт таблицы SQLite и один раз загружает ML-набор из CSV. При наличии таблицы компаний демо-профили не добавляются. Если CSV компаний недоступен, backend использует три явно синтетических профиля. Платежи и связи необязательны: если соответствующий файл отсутствует, эти данные остаются неизвестными.

ML-слой индексирует и сопоставляет записи, строит профиль компании с платежами и связями, обрабатывает новости и ранжирует ленту. Backend адаптер передаёт материалы из базы в ML-модуль и преобразует результат в API-ответ. Для инсайта выбранный ML-профиль сохраняется в SQLite, чтобы связать его с новостью и результатом анализа.

В данных есть повторяющийся синтетический ID компании. Такие ID исключаются из выдачи списка и при прямом запросе возвращают `409 ambiguous_company_id`; сервис не выбирает одну из конфликтующих строк произвольно.

CSV из `data/sample/` обезличены. Описание их колонок и назначения доступно в [`data/sample/README.md`](data/sample/README.md).

## Быстрый запуск

Требуется Docker с Docker Compose.

```bash
docker compose up --build
```

Откройте:

- Приложение: <http://localhost:8000>
- Swagger UI: <http://localhost:8000/docs>
- OpenAPI JSON: <http://localhost:8000/openapi.json>
- Проверка API и соединения с БД: <http://localhost:8000/health>

Остановка:

```bash
docker compose down
```

SQLite-файл по умолчанию находится в `data/alpha_hack.db` и сохраняется между перезапусками контейнера.

### Локальный запуск без Docker

Нужен Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

В macOS/Linux активируйте окружение командой `source .venv/bin/activate`.

## API

Все запросы и ответы — JSON. Для нового запроса middleware принимает входящий `X-Trace-Id` или создаёт идентификатор и возвращает его в заголовке ответа.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка приложения и базы данных |
| `GET` | `/api/companies?q=&limit=` | Список компаний и поиск по ID, ОКВЭД, отрасли, региону или городу |
| `GET` | `/api/companies/{company_id}?role=ceo\|cfo` | Профиль компании для выбранной роли |
| `GET` | `/api/feed?company_id=&role=ceo\|cfo&limit=&weights=` | Персонализированная лента; optional `weights` — JSON-объект из семи весов с суммой `1` |
| `GET` | `/api/ml/quality` | Диагностика CSV, проверка ML-профилей и синтетический benchmark ранжирования |
| `GET` | `/api/news/{article_id}?company_id=&role=` | Материал; при передаче компании — персональная оценка |
| `POST` | `/api/news/refresh` | Загрузить новости из настроенных RSS-лент |
| `POST` | `/api/insights` | Создать инсайт или вернуть ранее сохранённый для пары компания/новость/роль |
| `GET` | `/api/insights/{insight_id}` | Получить сохранённый инсайт |
| `POST` | `/api/insights/{insight_id}/questions` | Задать вопрос по инсайту |
| `GET` | `/api/insights/{insight_id}/questions` | Получить историю вопросов и ответов |
| `GET` | `/api/insights/{insight_id}/trace` | Получить трассу формирования инсайта |

Пример создания инсайта (возьмите `article_id` из `/api/feed`):

```json
{
  "company_id": "U_67",
  "article_id": "<article_id>",
  "user_role": "cfo"
}
```

Пример вопроса:

```json
{"question": "Как изменение ставки может повлиять на наши кредиты?"}
```

Профиль и лента принимают роли `ceo` и `cfo`. По умолчанию используется `ceo`. Поиск новостей обновляется только по ручному запросу — скрытого фонового планировщика нет.

Ошибки API содержат безопасный `code` и сообщение. Среди основных статусов: `400` — некорректное значение бизнес-параметра, `403` — неверный токен обновления RSS, `404` — компания, статья или инсайт не найдены, `409` — ID компании неоднозначен, `422` — ошибка валидации запроса, `503` — источники RSS недоступны. При ошибке RSS уже сохранённые новости остаются в базе и доступны API.

## ML-модуль (`ml/`)

- `data_access.py`, `dataset.py` — чтение, нормализация, индексация и сопоставление CSV.
- `company_profile.py` — профиль, финансовые признаки, платежи и связи компании.
- `news_processing.py` — нормализация новости, извлечение категорий и признаков.
- `deduplication.py` — группировка похожих публикаций/событий.
- `ranking.py`, `config.py` — объяснимый ранжировщик и его настройки.
- `contracts.py`, `integration.py` — проверка контрактов и адаптация к backend API.
- `eda.py`, `validate_dataset.py`, `evaluation.py` — исследование и оценка данных и ранжирования.

Профиль и результат ранжирования сохраняют причины, факторы, доказательства и сведения о пропущенных данных. Оценка основана на правилах и не является финансовой рекомендацией. Краткая документация ML также находится в [`ml/README.md`](ml/README.md).

## AI-модуль (`ai/`)

При `POST /api/insights` backend передаёт AI-агенту профиль компании, текст новости и результат её ML-оценки. `ai/agent.py` планирует шаги, классифицирует новость, при необходимости ищет связанные фрагменты, формирует структурированный анализ и запускает проверку результата. Trace сохраняется вместе с инсайтом. Вопросы по инсайту обрабатываются через `ai/ask.py` на основе новости и сохранённого анализа.

| Файлы | Назначение |
|---|---|
| `llm_client.py` | Вызовы настроенного совместимого API и кэширование ответов |
| `agent.py`, `prompts.py` | Планирование AI-анализа и подготовка инструкций модели |
| `bank_rag.py`, `test_data.py` | Поиск фрагментов локального корпуса; сейчас корпус содержит тестовые фрагменты |
| `schemas.py`, `parsing.py` | Структура ответа и разбор JSON-результата |
| `validation.py` | Проверки источников, полей и фактов ответа |
| `ask.py` | Уточняющие вопросы по новости и сохранённому инсайту |
| `run_test.py`, `stability_test.py`, `test_prompts.py` | Вспомогательные сценарии проверки AI и промптов |

Настроенные модели:

- `google/gemma-4-26b-a4b-it` — классификация темы новости.
- `z-ai/glm-5.3-flash` — интерпретация и ответы на вопросы.

Модуль обращается к совместимому с OpenAI API провайдеру, указанному в конфигурации. Чтобы включить вызовы моделей, создайте в корне `.env` (на основе `.env.example`) и задайте `LLM_API_KEY` и `LLM_BASE_URL`. Без доступной LLM API остаётся доступным, но создание AI-инсайта может сохранить результат со статусом `unavailable`; такой ответ не следует считать анализом модели.

### Корпус банковских материалов и ограничения AI

В `data/bank_analytics/` находятся три PDF и `notes.md`. Текущий `ai/bank_rag.py` **не извлекает содержимое из PDF**: поисковый корпус сейчас собирается из тестовых фрагментов в `ai/test_data.py` и ищет совпадения по основам слов. Поэтому наличие PDF на диске само по себе не означает, что их выводы доступны агенту. Позиция банка должна появляться только при наличии найденного подтверждённого фрагмента; в противном случае она остаётся пустой.

Проверка AI-ответа сочетает проверку схемы и эвристические проверки текста, поэтому не гарантирует обнаружения всех смысловых ошибок. Формулировки могут меняться между вызовами модели. Данные профиля передаются настроенному провайдеру модели. Не используйте с внешним провайдером персональные или конфиденциальные данные без соответствующего разрешения.

Сценарии `ai/run_test.py`, `ai/stability_test.py` и `ai/agent.py` отправляют запросы к LLM и могут расходовать лимит провайдера. `ai/test_prompts.py` только печатает пример промпта. Для запуска сценариев, вызывающих модели, нужен настроенный `.env`; выполняйте их осознанно. Примеры результатов находятся в `results/`; это артефакты прошлых прогонов, а не гарантированный результат нового вызова.

## Frontend (`frontend/`)

Интерфейс позволяет найти компанию по ID, отрасли или региону, выбрать роль, открыть профиль, читать персональную ленту, отфильтровать новости поиском, запросить обновление RSS, получить AI-инсайт и задать вопрос по нему. В профиле отображаются финансовые признаки, платежи, связи компаний, пропуски, некорректные значения и источники полей. В разборе новости доступны вклады и веса факторов, доказательства, версия алгоритма и объединённые источники. В разделе качества ML можно изменить веса для текущей ленты; настройка не сохраняется глобально.

Раздел «Качество ML» запрашивает диагностику исходных CSV, проверку профилей и отчёт ранжирования на синтетическом размеченном наборе. Отчёт доступен в API через `GET /api/ml/quality`; он рассчитывается по запросу и кэшируется до изменения входных CSV. Контракт новости проверяется при каждом запросе ленты. Метрики контрольного набора не являются оценкой качества на реальном новостном потоке.

Клиентский код разделён по ответственности:

- `frontend/index.html` — семантическая разметка страницы и диалога разбора новости.
- `frontend/styles.css` — визуальная система, сетка и адаптивные состояния для небольших экранов.
- `frontend/app.js` — точка входа, состояние страницы и обработчики пользовательских действий.
- `frontend/js/api.js` — HTTP-запросы к REST API и разбор ошибок.
- `frontend/js/render.js` — отрисовка профиля, ленты, карточек и AI-разбора.
- `frontend/js/dom.js` — безопасные DOM-утилиты и форматирование дат и сумм.

Доступность интерфейса поддерживают клавиатурный переход к содержимому, видимый фокус, подписанные поля и диалог, а также режимы уменьшенной анимации и повышенной контрастности.

## Данные и конфигурация

Скопируйте `.env.example` в `.env` и переопределите нужные параметры:

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `APP_NAME` | Название FastAPI-приложения |
| `DATABASE_URL` | SQLite: `sqlite:///./data/alpha_hack.db` |
| `CORS_ORIGINS` | Разрешённые CORS origins через запятую |
| `RSS_FEEDS` | RSS-ленты Банка России через запятую |
| `REQUEST_TIMEOUT_SECONDS` | Таймаут запроса к RSS, по умолчанию `8` |
| `MAX_FEED_ITEMS` | Максимум записей на одну RSS-ленту за обновление, по умолчанию `30` |
| `NEWS_REFRESH_TOKEN` | Необязательная защита `POST /api/news/refresh`; передаётся в `X-Refresh-Token` |
| `COMPANIES_CSV_PATH` | CSV компаний |
| `PAYMENTS_CSV_PATH` | CSV платежей |
| `PERSON_LINKS_CSV_PATH` | CSV связей физических лиц и компаний |
| `LLM_API_KEY` | Ключ совместимого с OpenAI API провайдера для AI-модуля |
| `LLM_BASE_URL` | Базовый URL API этого провайдера |

В Docker Compose CSV смонтированы в контейнер по путям `/app/data/sample/...`. Не коммитьте `.env`, ключи моделей или локальную базу данных.

## Тестирование и coverage

Автотесты не требуют реальных RSS-запросов или ключа LLM; внешние вызовы подменяются тестами. Запуск полного набора в Docker:

```bash
docker compose --profile test run --build --rm tests
```

Локально:

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

HTML-отчёт coverage сохраняется в `test/coverage_html/`:

```bash
docker compose --profile test run --build --rm tests python -m pytest --cov=backend --cov-report=html:test/coverage_html
```

Откройте `test/coverage_html/index.html`. Каталог отчёта исключён из Git.

Покрытие набора включает API и обработку ошибочных запросов, контракты, CSV-профилирование и сопоставление, персонализацию, RSS-нормализацию и дедупликацию, сохранение инсайтов и вопросы. Отдельные AI-скрипты для ручных прогонов не заменяют unit-тесты `ai/`.

## Известные ограничения

- Демо-версия использует SQLite и не запускает миграции схемы.
- Для RSS нет фонового расписания; его запускает клиент API.
- Корпус RAG пока использует тестовые фрагменты, а не извлечённый текст PDF.
- Доступ к API не требует пользовательской аутентификации; токен можно включить только для обновления RSS.
- Ранжирование и AI-анализ служат поддержкой ознакомления с новостями, а не финансовой или банковской рекомендацией.
- Перед публичным развёртыванием необходимы авторизация, миграции, эксплуатационный мониторинг, контроль частоты запросов и проверка условий использования внешнего LLM/RSS.
